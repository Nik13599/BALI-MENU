# Общая админка: подготовка интерфейса к работе

Область: `admin.html`, конструктор, страницы «О клубе» и «Информация». Отдельная рабочая страница `preorders.html` и её серверные операции не изменены.

## Исправления

- Устранены ReferenceError при выборе элементов конструктора: отсутствовали `inlineEditor` и обработчик двойного клика. Двойной клик открывает текст в редакторе.
- Список рекламных слайдов больше не обращается к удалённой переменной `isBuiltin`. Сохранённые предложения можно открыть и удалить обычными действиями с подтверждением.
- Конструктор блокирует изменения до загрузки черновика и во время записи. Ошибка загрузки не позволяет опубликовать пустую модель. Ошибка записи сохраняет правки для повтора.
- Смена аккаунта очищает модель, выбор, буфер стилей и историю. Поздние результаты сохранения/обработки изображений предыдущего аккаунта игнорируются. Публикация по-прежнему атомарно записывает черновик и публичную версию одним batch.
- Возврат опубликованной версии получает актуальные данные из базы, включая публикацию другого сотрудника; отмена возвращает прежний черновик.
- Добавлено предупреждение браузера при закрытии страницы с несохранённым черновиком.
- Копирование настроек использует выбор устройства с русскими названиями. Результат можно отменить.

## Интерфейс и скорость

- Уплотнены навигация, обзор, карточки, поля и конструктор; настройки разбиты на сворачиваемые группы. На мобильных остаются читаемые поля 16 px и кнопки от 40 px.
- Статусы, бонусы/QR и справка по переводам открываются отдельно. Выбор гостя автоматически раскрывает редактор статуса. Недоступная форма служебного перевода скрыта; перевод самим гостем продолжает работать.
- Навигация и внутренние страницы используют локальные SVG. Старый декоратор сохраняет уже нанесённые иконки.
- Живой iframe конструктора загружается при первом открытии раздела, а не при входе в админку.
- Убрана блокирующая весь гостевой интерфейс заставка, ожидавшая полный набор снимков данных и изображений до 18 секунд. Страницы доступны сразу; существующие читатели данных продолжают получать актуальные публикации, без изменения прав доступа или сохранённых данных. Внешний вид главной не переработан.
- Сохранено по одному собранному CSS на гостевую страницу и админку; новые иконки не создают сетевых запросов.

## Проверка

Регрессии используют реальные формы и обработчики, заменяя только Firebase транспорт изолированными данными: загрузка/ошибка черновика, редактирование, отмена/повтор, атомарная публикация, ошибка записи, выход во время записи, копирование между устройствами, редактирование/удаление рекламного слайда, работа внутренних страниц без внешней сети. Четыре размера: 320, 390, 820 и 1440 px.

Дополнительно: проверки исходников, backend-тесты, генерация CSS, проверка неопределённых имён JavaScript в модулях общей админки и существующие браузерные сценарии каталога, мероприятий, QR/бонусов и конструктора. Реальные пользовательские данные для тестирования не создаются и не изменяются.

## Публикация и проверка домена

Основной сайт обслуживает Cloudflare Pages, проект `bali-nightclub-menu` с автоматической публикацией `main`. Предпросмотры веток отключены настройками проекта. Выполнена локальная сборка `node cloudflare-pages/build.mjs`.

Публичная конфигурация Firebase подтверждает разрешённый домен `baliminsk.by`; `www.baliminsk.by` отсутствовал. Для рабочего Google-входа настроено точечное Cloudflare Single Redirect: только `http.host eq "www.baliminsk.by"`, 301 на `https://baliminsk.by` с исходным путём и query string. Перенаправление проверено HTTP-запросом. DNS и разрешения Firebase не менялись. Ruleset `e543d6b38a184d4da90dd162b5dbd42b`, правило `7f6e85baccb34e82ad6a8ecd79405763`.

Обновлены изолированные фикстуры афиш: они передают снимок через реальное событие `bali:events`, как текущий читатель данных, вместо изменения внутреннего массива. Исправлена геометрия календаря на ПК: старое соотношение карточки 9:16 растягивало контейнер и конфликтовало с центрированием. Контейнер теперь получает естественную высоту квадратной афиши и кнопок; локальная перспектива и порядок наложения сохранены. Проверка ожидает итогового измерения с прежним допуском 3 px. Общие стили новой админки ограничены классом `bali-admin-workspace`, поэтому отдельная рабочая страница предзаказов их не получает.

Критическое правило закрытого окна входа находится в HTML: `aria-hidden="true"` действительно скрывает его даже при отсутствии основного CSS, чтобы невидимое окно не перехватывало нажатия.

Устранено искажение афиш на планшете: карточка больше не растягивается по высоте ряда и сохраняет существующие квадратные пропорции; количество и расположение карточек не менялись. Изолированный тест рабочей страницы предзаказов теперь скрывает экран входа при показе панели, как настоящий обработчик авторизации. Финальные три регрессии воспроизведены и проверены отдельно.
