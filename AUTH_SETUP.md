# BALI MENU — настройка регистрации гостей

## Как работает регистрация
1. Пользователь открывает `index.html` и нажимает «Войти / Регистрация».
2. Нажимает «Войти через Google». Firebase Authentication проверяет Google-аккаунт и его почтовый адрес.
3. Обязательно заполняет **имя** и **номер телефона** в международном формате (пример: `+375291234567`).
4. **Email** автоматически берётся из Google и недоступен для редактирования.
5. Firestore записывает профиль в документ `users/{firebaseAuth.uid}`, доступный только владельцу.
6. При повторном входе через тот же Google-аккаунт имя и номер телефона подгружаются из профиля; пользователь может их изменить.
7. Пока профиль не заполнен, оформление заказа блокируется.

**Важно:** email действительно подтверждён провайдером Google, но телефон пока НЕ подтверждается по SMS. Регистрация работает только после выполнения настройки ниже.

## Подключение (владелец Google/Firebase-проекта)

1. Откройте [Firebase Console](https://console.firebase.google.com/) и создайте отдельный проект **BALI MENU** (или используйте отдельный согласованный существующий проект). Не используйте проект, от которого уже зависит другая работающая система BALI, без проверки.
2. В **Authentication → Sign-in method** включите провайдер **Google**. Укажите обязательный адрес электронной почты для поддержки проекта, когда Firebase попросит его.
3. В **Authentication → Settings → Authorized domains** добавьте домен фактического сайта. Для GitHub Pages — `nik13599.github.io` (проверьте точное написание своего домена).
4. В **Firestore Database** создайте базу данных и примените `firestore.rules` **до размещения сайта в интернете**. По умолчанию закрыт доступ ко всем коллекциям, кроме собственного документа `users/{uid}`.
5. В **Project settings → Your apps** зарегистрируйте веб-приложение. Скопируйте `apiKey`, `authDomain`, `projectId`, `appId` в `firebase-config.js`. Это публичные параметры конфигурации веб-приложения, не секретный ключ.
6. Загрузите сайт на HTTPS (GitHub Pages / Firebase Hosting) и проверьте вход на телефоне и компьютере. Из-за политики браузера Google-авторизация может требовать настройки redirect / домена авторизации.
7. Проверьте: без входа оформление закрыто; без имени и телефона невозможно создать профиль; после входа повторно профиль восстановлен; чужой UID недоступен в Firestore; правила не позволяют подменить email и UID.
8. Для тестирования используйте отдельные тестовые аккаунты. Перед реальным использованием опубликуйте политику обработки персональных данных, определите права сотрудников и сроки хранения.

## Схема профиля Firestore

```json
{
  "uid": "Firebase Authentication UID",
  "email": "подтверждённый Google email",
  "name": "Имя посетителя",
  "phone": "+375291234567",
  "createdAt": "серверная отметка времени",
  "updatedAt": "серверная отметка времени"
}
```

Идентификатор пользователя (UID) берётся из Firebase Authentication, не из поля формы. Администратор не получает права чтения профилей через браузер — для обработки заказов нужен отдельный защищённый серверный API.

## Пока НЕ работает
- Настоящий приём/редактирование заказов: нужен сервер с проверкой Firebase ID Token и серверным пересчётом цены.
- Запись заказов в Google Таблицу по датам: интеграция ещё не развернута.
- Полноценная защищённая админ-панель: небезопасный пароль шаблона отключён.
- SMS-верификация номера телефона и смена email без входа в другой Google-аккаунт.

**Не публикуйте старый `Code.gs` без переработки.** Его функции создания заказов и старого сброса данных отключены намеренно.
