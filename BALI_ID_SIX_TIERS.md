# BALI ID — шесть категорий (2026)

Статусы: **Member · Silver · Gold · Platinum · Black · Private**. Цветовые решения оформлены по предоставленным референсам: Member — зелёный лайм, Silver — серебристый, Gold — золотой, Platinum — ледяной голубой, Black — чёрно-белый, Private — янтарно-оранжевый.

## Интерфейсы

- Гость: `index.html#id`. Одна интерактивная двусторонняя карта с реальным именем и индивидуальным номером; цвет и название статуса приходят из `guestPrivileges/{uid}`. Обратная сторона содержит статусные привилегии и персональные преимущества. Свайп и 3D-переворот не изменены.
- Администратор: `admin.html` — блок BALI ID · управление Privilege; назначение шести уровней и настройка описаний/преимуществ.
- Директор: `director-id.html` — отдельный служебный интерфейс, вход через Google, поиск гостя по номеру BALI ID, назначение уровня и персональных привилегий. Роль должна быть проверена серверными правилами Firestore.

## Правила выдачи

1. После регистрации новый пользователь получает **Member**. При отсутствии `guestPrivileges/{uid}` клиент создаёт только Member с пустым массивом дополнительных привилегий.
2. Переход на любой другой статус, возврат на Member и редактирование личных привилегий — только через подтверждённого администратора или директора.
3. Гость не может изменить себе уровень: Firestore Rules допускают самостоятельную **create Member**, но запрещают пользователю **update** или **delete** присвоенного статуса.
4. Имеющиеся уровни ранее зарегистрированных пользователей не перезаписываются.
5. Права директора не возникают от перехода на служебную страницу, а назначаются вручную владельцем Firebase.

## Назначение директора (владелец Firebase)

Firebase Console → Firestore Database → создать коллекцию `staffRoles` (если её ещё нет) → документ с ID **UID директора из Firebase Authentication**. Поля:

- `role` (string): `director`
- `active` (boolean): `true`

Клиенту запрещено создавать или менять `staffRoles`. Администраторы продолжают использовать ранее выданную роль `admins/{uid}.active=true`. Поддержка director входит только в правила `guestPrivileges`; роли директора НЕ дают полный доступ к админ-панели, заказам или финансовой отчётности.

## Обязательное развёртывание

**GitHub Pages публикует только HTML/CSS/JS.** Firestore Rules самостоятельно при публикации GitHub Pages не изменяются.

Для безопасного назначения уровней требуется отдельно опубликовать обновлённый `firestore.rules` в Firebase Console для проекта `bali-menu-5a48b` или через команду `firebase deploy --only firestore:rules --project bali-menu-5a48b` с правами владельца.

До публикации правил визуальные шесть категорий будут доступны, но создание Member-документа гостем или назначение Gold/Platinum директором может завершаться `permission-denied` на существующей базе. Это не должно обходиться изменением клиентского кода или отключением правил.

## Важные ограничения

- Категория карты сама по себе НЕ начисляет бесплатные коктейли, шоты, кальяны или проходы и не создаёт скидки. Для этого требуется отдельная серверная система начислений/списаний из PR #30.
- Сведения на обороте о клубных преимуществах — описание статуса. Фактические бонусы должны храниться и контролироваться отдельно.
- Правила шести статусов редактируются администратором. Существующие сохранённые описания четырёх прежних статусов не перезаписываются автоматически, их можно обновить в редакторе.
- Точное пиксельное использование изображения из примера потребовало бы отдельные чистые брендовые фоны без текстовых надписей: веб-интерфейс использует CSS-оформление с динамическими данными, вдохновлённое предоставленными примерами.

## Приёмочные проверки

1. Новый аккаунт → Member → сохранённый BALI ID → выход/вход → тот же Member и номер.
2. Администратор назначает Gold и Platinum, а затем любой другой из шести статусов → цвет обеих сторон и название обновляются.
3. Директор с вручную назначенной ролью может найти гостя и поменять категорию; обычный гость не может.
4. Попытка самому записать Silver/Gold/Platinum/Black/Private, обновить Member или выдать роль директора получает `permission-denied`.
5. Свайп обеих сторон, масштаб iPhone, адаптация ПК и открытие QR без изменений.
6. Редактор правил в админке сохраняет все шесть уровней, включая Gold и Platinum.
