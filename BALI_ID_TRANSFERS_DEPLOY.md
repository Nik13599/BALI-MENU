# BALI ID: публикация рабочих переводов

## Что уже находится в коде

- Интерфейс гостя на `index.html`: `Перевести` и `История операций`.
- Проверка шестизначного номера через `previewBaliRecipient`; возвращается только отображаемое имя и номер карты, без телефона/e-mail/UID.
- Выбор нескольких количественных бонусов и разного количества для каждого.
- Подтверждение запускает `transferBaliBenefits`: **одна серверная транзакция** уменьшает остаток отправителя, увеличивает остаток получателя и записывает две истории.
- `listMyBaliHistory` даёт гостю только его операции. Каждая запись включает тип, количество, время по Минску, отправителя или получателя и основание, если оно было.
- Сотрудник с ролью директора/администратора начисляет количественные бонусы через `director-id.html`. Текстовые статусы Member/Silver/Gold/Platinum/Black/Private не переводятся.

## Почему GitHub Pages недостаточно

GitHub Pages раздаёт HTML/CSS/JS, но **не исполняет Firebase Cloud Functions**. До развёртывания сервера нельзя обещать реальные переводы/историю. Нельзя добавлять прямые клиентские записи в `guestWallets` — это позволило бы подделывать остаток.

## Развёртывание

1. В Firebase-проекте `bali-menu-5a48b` проверьте Firestore и план Blaze (Cloud Functions 2nd gen).
2. В GitHub: Settings → Environments → `firebase-production` установите variables `FIREBASE_WIF_PROVIDER` и `FIREBASE_DEPLOY_SERVICE_ACCOUNT` для доверенного Google Workload Identity Federation. Аккаунту нужны IAM-разрешения для Firebase Functions/Cloud Run, Firestore rules/indexes и установки service-account identity; эти права выдаёт владелец Google Cloud. **Не записывайте JSON private key в репозиторий.**
3. В GitHub: Actions → `BALI ID — Deploy Firebase Backend` → Run workflow → подтвердите `bali-menu-5a48b`.
4. Убедитесь, что job завершилась `success`, в Firebase консоли функции `previewBaliRecipient`, `transferBaliBenefits`, `listMyBaliHistory`, `issueBaliQuantity` доступны в `europe-west1`, а составной индекс `walletOperations` построен.
5. Директор на `director-id.html` назначает тестовому аккаунту 3 `shot` с флагом «разрешить перевод». Для проверки нужны две зарегистрированные карты.
6. На первом аккаунте BALI ID нажмите «Перевести», найдите второго по номеру, проверьте имя, выберите 1 шот и подтвердите. Проверьте остатки 2/1 и истории −1/+1. После этого попробуйте перевести 3 шота: операция должна отклониться без изменений.
7. Проверьте параллельные переводы последних единиц и повторную отправку одного requestId (повтор не должен списывать второй раз).

**Пока production deploy не подтверждён, карточки и окна доступны, но настоящий перевод ещё не активирован.**

> Cloud Functions из старого открытого PR #30 не включены в этот deployment. В частности, `issueGuestQr` (для одноразового QR на существующей карте) требуется публиковать отдельно после тестов; не выдавайте его за активный.
