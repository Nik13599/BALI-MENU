# Категории и карточки товаров BALI MENU

Панель: https://nik13599.github.io/BALI-MENU/admin.html

## Один раз включить сохранение категорий

Новые категории сохраняются в коллекции `categories` проекта Firebase `bali-menu-5a48b`.
В клиентском интерфейсе нет прямого доступа к настройкам базы, поэтому новые
правила безопасности нужно **один раз вручную опубликовать**:

1. Откройте https://github.com/Nik13599/BALI-MENU/blob/main/firestore.rules
   и нажмите **Raw**, затем скопируйте весь файл.
2. Откройте https://console.firebase.google.com/project/bali-menu-5a48b/firestore/rules .
3. Полностью замените предыдущие правила скопированным текстом и нажмите **Publish**.
4. Войдите в админ-панель через разрешённый Google-аккаунт.

Не нужно вручную создавать коллекцию `categories`: первый сохранённый раздел
появится там автоматически.

## Как устроено меню

- Раздел **Меню и цены** содержит кнопки **Добавить блюдо** и **Новая категория**.
- **Новая категория** открывает отдельное окно. Введите название, порядок
  отображения и нажмите **Сохранить категорию**. Она останется в базе, даже
  если в ней пока нет блюд.
- **Добавить блюдо** открывает карточку товара. В ней выбирается существующая
  категория через выпадающий список; кнопка **+ Новая** рядом со списком
  позволяет создать категорию, не покидая карточку.
- Новому блюду автоматически присваивается свободный числовой ID. При
  одновременном добавлении несколькими администраторами запись с занятым ID
  не перезаписывается; при сообщении о конфликте откройте карточку заново.
- Каталог отображается группами: **категория → товары**. Нажмите название
  группы, чтобы свернуть/развернуть список; поиск работает по названию, ID
  и категории.
- **Изменить** открывает заполненную карточку товара. Успешное сохранение
  закрывает окно; при ошибке окно остаётся открытым с сообщением.
- Для пустых категорий, созданных отдельно, доступно **Удалить**. Категория,
  в которой есть товары, не удаляется через интерфейс во избежание путаницы.

Ранее импортированные товары и их названия категорий не изменяются. Старые
категории собираются из документов `menu` автоматически и доступны для
выбора; копировать/мигрировать их в `categories` не требуется.

Доступ к `categories` имеют только аккаунты, которым назначена активная
роль в `admins/{UID}`. Публичный гостевой каталог продолжает читать только
существующие товары из `menu`.

## Проверки

Проверка исходного кода выполняется на каждом push в GitHub Actions.
Проверить вход и запись новой категории в **реальном Firebase** можно
только после публикации новых правил. Сначала создайте тестовую категорию
«Проверка», убедитесь, что она появилась в списке, а затем удалите её,
если она пустая.
