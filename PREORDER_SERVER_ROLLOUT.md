# Безопасный ввод серверного предзаказа BALI

## Что реализовано

- `submitBaliPreorder` (Cloud Functions, регион `europe-west1`) заново проверяет подтверждённый Firebase аккаунт, профиль, согласие, конкретное мероприятие, дедлайн и фактическую кухонную позицию из `menu/{id}`. Принимаются **1–12 разных блюд**, количество **1–50** каждого вида. Цена, название, контактные данные и номер заказа **не** берутся из браузера.
- Одна Firestore транзакция записывает заказ, полный набор блюд, отдельный счётчик по `eventId`, квоту частоты и квитанцию идемпотентности. Повтор по тому же идентификатору и телу возвращает старый результат без второго заказа; изменённое тело с тем же ID отклоняется. Можно изменять `pending` и переносить его на другое мероприятие с новой нумерацией.
- Ограничение от массового создания: максимум **12 новых серверных операций на один аккаунт за 60 секунд**. Идентичный повтор уже успешного запроса не учитывается. Правила Firestore запрещают гостю менять серверные квитанции и счётчик частоты.
- Для действующего сайта **по умолчанию оставлен прежний checkout**. Разделение необходимо, потому что Cloud Functions ранее не удалось развёрнуть из-за отсутствующего Workload Identity Provider (issue #84).

## Порядок безопасного включения

1. Устранить блокер [#84](https://github.com/Nik13599/BALI-MENU/issues/84). Проверить GitHub Settings → Environments → `firebase-production`: `FIREBASE_WIF_PROVIDER` и `FIREBASE_DEPLOY_SERVICE_ACCOUNT`. Переменные должны быть связаны с разрешённым доверительным соединением GitHub → Google Cloud для проекта `bali-menu-5a48b`. Не передавать закрытые JSON-ключи в репозиторий. Для старого workflow environment называется `firebase-backend`; не путать их.
2. Проверить план Firebase, роли сервисной учётной записи, структуру и опубликованные Rules. Развернуть обновлённый `firestore.rules`, если он ещё не опубликован. При **отсутствии** `settings/preorderSecurity` прямые клиентские заказы по-прежнему разрешены, поэтому этот шаг не переключает работающий сайт.
3. В GitHub Actions вручную выполнить **BALI ID — Deploy Firebase Backend** после проверки списка разворачиваемых Cloud Functions. Убедиться, что сервер действительно создал `submitBaliPreorder` в `europe-west1`. Отдельно проверить существующие переводы, историю и QR.
4. До включения флага протестировать новую callable-функцию на двух тестовых аккаунтах и нескольких мероприятиях, проверить цену, пустую корзину, повтор `requestId`, истечение дедлайна и запрет прав постороннего аккаунта. Произвести очистку только созданных тестовых записей из рабочих данных по утверждённой процедуре.
5. Только после успешной серверной приёмки вручную создать документ Firestore `settings/preorderSecurity`: `backendRequired: true`, `updatedAt`: **serverTimestamp**. Его можно создать из административного Firestore-клиента с правами админа и вызовом `serverTimestamp()` либо через подготовленный внутренний управляющий инструмент. **Не записывать произвольный Timestamp из консоли:** правила требуют `request.time`.
6. Проверить, что текущая версия `orders-firestore.js` опубликована на GitHub Pages, затем оформить новый заказ и редактирование с реального тестового профиля. При `backendRequired=true` браузер обращается к callable, а прямые записи гостей в `orders`, `orderCounters` и `orders/{id}/items` блокируются. Гость может отменить собственный заказ, персонал по-прежнему редактирует заявки в админке.
7. При проблеме с Functions временно **приостановить оформление**, отобразив явное сообщение об ошибке. Отключать `backendRequired` допустимо только как осознанный возврат к старой модели, поскольку защита всей корзины исчезнет. Автоматического небезопасного fallback нет.

## Проверки перед выпуском

```sh
npm ci
node scripts/test-preorders.mjs
npm test
npm run test:firebase
npm run test:browser
```

**Ограничение статуса:** наличие кода, CI и успешного GitHub Pages деплоя не означает, что Cloud Functions опубликованы в рабочем Google Cloud. Пока `backendRequired` не включён после указанного порядка, публичная версия ещё использует старую запись напрямую в Firestore.
