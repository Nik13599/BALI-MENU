# BALI ID · Privilege Control

Эта ветка добавляет **рабочий прототип серверной системы бонусов**, интегрированный с уже существующими `baliIds/{uid}`, `users/{uid}` и `guestPrivileges/{uid}`. Карта гостя располагается в существующем профиле на `index.html`. Интерфейсы сотрудников/директора открываются по адресу `staff.html`.

## Роли и доступ

| Роль | Разрешённые операции |
| --- | --- |
| Гость | Своё имя, ID, уровни привилегий, бонусы, собственный временный QR |
| Бармен | Проверка QR, списание коктейлей / шотов / кальянов, подтверждение скидки по номеру чека |
| Хостес | Проверка QR и бесплатного входа, отметка прохода, запрет повторной отметки |
| Директор | Все действия бармена и хостес, начисление, ручное списание с причиной, поиск гостя по BALI ID, журнал всех операций, выдача ролей бармену и хостес |
| Администратор | Всё, что директор, плюс существующая админ-панель управления сайтом |

**Важно:** статус Member / Silver / Black / Private не связан автоматически с денежными бонусами. Бонусы назначаются персонально; повышение статуса не начисляет их скрытым образом.

## Развёртывание Firebase (обязательно перед боевым использованием)

1. Сделайте резервную копию Firestore. Убедитесь, что проект Firebase `bali-menu-5a48b` подключён к рабочему аккаунту. **Для Cloud Functions второго поколения обычно нужен план Blaze и включённый биллинг** — сначала проверьте тариф в Firebase Console.
2. На локальной машине выполните `firebase login`, `firebase use bali-menu-5a48b`, затем `npm install --prefix functions`.
3. Опубликуйте правила: `firebase deploy --only firestore:rules`.
4. Опубликуйте серверную логику: `firebase deploy --only functions:privileges`. Она размещается в регионе `europe-west1`.
5. После тестирования в Firebase Emulator Suite опубликуйте Hosting или перенесите статические файлы на используемый GitHub Pages. Файлы `functions/**` публично НЕ размещать.
6. В Firestore Console создайте документ `staffRoles/{DIRECTOR_FIREBASE_UID}` с точными полями `role` (строка `director`), `active` (boolean `true`). **Права директора выдаются исключительно вручную доверенным владельцем Firebase**. Альтернативно действующий `admins/{uid}.active=true` уже предоставляет роль администратора.
7. Сотрудники заходят в `staff.html` через Google. Если роль не назначена, экран показывает их UID. Директор вводит этот UID в своём интерфейсе и назначает только роли `bartender` или `hostess`; присвоить директора через браузер нельзя.

Веб-конфигурация Firebase публичная по определению, но сервисные ключи Firebase Admin SDK **никогда не должны попасть** в браузер или GitHub. На стороне облачной функции Admin SDK использует сервисную идентичность среды исполнения.

## Как работает QR

- Гость авторизуется, активирует BALI ID, нажимает **Показать QR-код для сотрудника**.
- Сервер создаёт криптографически случайный одноразовый токен. Срок действия — 90 секунд; на карте выводится QR и резервная текстовая форма `BALI:...`.
- Сотрудник сканирует QR с помощью `BarcodeDetector` там, где браузер его поддерживает. В неподдерживаемом браузере код можно вставить вручную. Камере нужен HTTPS и разрешение пользователя.
- Сервер проверяет подпись входа Google, назначенную роль, срок QR и фактический баланс. Подтверждённая операция одновременно изменяет остаток, отмечает QR использованным и записывает журнал через Firestore transaction.
- По одному QR выполняется одна операция. Для следующей операции гость нажимает обновление QR.

## Форматы привилегий

- `cocktail`, `shot`, `hookah`: количество (1–500 на начисление), можно списать несколько единиц за раз (1–50 за операцию).
- `entry`: количество проходов либо безлимит до обязательного срока; можно ограничить событием.
- `discount`: процент 1–100, категория кухня/бар/все разрешённые позиции, необязательная дата окончания. Подтверждение обязательно привязано к номеру чека.
- Каждое начисление может иметь дату истечения и ID события. Привилегия на конкретное событие действует только при совпадении идентификатора.
- Повторный проход на тот же ID события, а без ID — в течение того же календарного дня Минска, блокируется.

**Ограничение:** подтверждение скидки только фиксирует действие в BALI. Оно пока НЕ меняет сумму чека в кассовой программе и не заменяет законное подтверждение возраста для алкоголя/кальянов. Интеграция с POS — отдельная задача.

## Коллекции Firestore

| Коллекция | Содержание |
| --- | --- |
| `guestWallets/{uid}` | Массив выданных бонусов и остатков, доступен на чтение только гостю и администратору; все изменения через Cloud Functions |
| `staffRoles/{uid}` | Роль и активность сотрудника; клиентам изменение запрещено |
| `qrSessions/{sha256(token)}` | Временная QR-сессия, время завершения и однократного использования |
| `qrIssuance/{uid}` | Ограничение частоты создания QR |
| `guestEntries/{sha256(uid:eventOrDay)}` | Защита от повторного бесплатного входа |
| `discountReceipts/{sha256(uid:receipt)}` | Предотвращение двойного подтверждения одного чека |
| `walletOperations/{operationId}` | Неизменяемый для браузеров журнал действий с UID сотрудника и гостя, временем и причиной |

Коллекции операций не доступны из клиентского Firestore; директор читает их через серверный callable `listPrivilegeAudit`. Для аудита вне приложения используйте Firebase Console с ограниченными правами.

## Что обязательно проверить до выхода в продакшен

- Настройку прав в Emulator Suite: неавторизованный, гость, бармен, хостес, директор, администратор.
- Одновременное списание последнего бонуса с разных телефонов, повторное использование QR, истёкший QR, отключённую роль сотрудника, ошибки сети и повторные запросы.
- Сроки действия бонусов, безлимитный/количественный вход, повторный вход в пределах одного дня/события.
- Сквозной проход на iOS и Android, в том числе резервный ввод кода.
- Процедуру возврата ошибочно списанных бонусов (в текущей версии есть ручное начисление по решению директора; полноценный связанный возврат с ссылкой на исходную операцию надо доработать отдельно).
- Защиту от злоупотреблений и мониторинг расходов на Cloud Functions/Firestore.

**Статус:** код интеграции находится в ветке GitHub. Само наличие файлов не означает, что Firebase Functions/Rules и сайт опубликованы или прошли реальные испытания.
