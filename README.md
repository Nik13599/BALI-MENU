# BALI MENU

Гостевой сайт BALI NIGHTCLUB (Минск): мероприятия, кухня, барная/кальянная/чайная карты, предзаказы к столику, профиль и BALI ID. Отдельные страницы: `admin.html` для администратора и `director-id.html` для управления привилегиями.

## Запуск

Требуются Node.js 22+ и Python 3. Для Firebase Emulator также Java 21+.

```sh
npm ci
npm start
# http://localhost:8000
```

Для публичного чтения сайт использует конфигурацию `firebase-config.js`. Google-вход требует включённого Google provider и разрешённого домена в Firebase Authentication. Публичная конфигурация не даёт административных прав: они проверяются в `firestore.rules` по вручную назначенным документам `admins/{uid}` и `staffRoles/{uid}`.

## Стили и изображения

Порядок стилей задаёт `styles/entries.json`. Файлы источников сохраняются для поэтапного рефакторинга, а браузер загружает один сжатый CSS для гостевого сайта и один для админки. Сборка сохраняет последовательность правил; версии в HTML вычисляются из содержимого.

```sh
npm run build:styles
npm run check:styles
npm run build:images
```

`generated/` и адаптивные фото включены в Git — сайт работает и на статическом хостинге без сборки на сервере. После изменения исходного CSS нужно запустить `build:styles`. Скрипт `build:images` создаёт WebP/AVIF шириной 320/640/960/1600 и манифест из сохранённых оригиналов галереи. Фотографии не редактируются содержательно; меняются формат и размер.

## Проверки

```sh
npm test
npx playwright install chromium
npm run test:browser
npm run test:firebase
```

Браузерные тесты блокируют внешний Firebase. Сквозной тест выполняет настоящий клиентский модуль заказов против Auth/Firestore/Storage Emulator в `demo-bali-menu`, проверяет профиль, цену из каталога, изменение, подтверждение, отмену и запреты доступа. Скрипт намеренно не допускает рабочий project ID. Тестовые данные и имитация Google-токена существуют только в эмуляторе; это не проверка реального OAuth в рабочем проекте.

## Работа персонала

- Для нового события стандарт — **23:00–06:00 по Минску**. В форме доступны вечерний пресет **19:00–22:30** и произвольное время. Старые события автоматически не переписываются. Закрытие предзаказов настраивается отдельно от окончания события.
- В обзоре админки есть проверка незаполненного расписания и описаний блюд. Составы и специальные часы вводятся по утверждённым данным.
- Уведомления работают **внутри открытого сайта**: гостю об изменении статуса его заказа, сотруднику о новом предзаказе. Первый снимок загружается тихо, повторные снимки и перезагрузка не дублируют уже замеченные статусы. При смене аккаунта лента очищается. В закрытом браузере уведомления не доставляются.
- Диагностика админки показывает состояние текущего браузера. Экспорт содержит только область, код и время — без сообщений ошибок, токенов и персональных данных. Серверные callable-функции пишут структурированные события `bali.callable` с операцией, исходом и длительностью.

## Публикация и рабочий Firebase

Конфигурация Hosting включает CDN-кеширование фото/шрифтов и версионированного CSS, перепроверку HTML и базовые HTTP-заголовки. Публикация и обновление правил требуют доступа владельца к Firebase; изменение Git-ветки само по себе их не развёртывает. Используйте существующие ручные workflow и [FIREBASE_DEPLOY.md](FIREBASE_DEPLOY.md).

Для фото из админки подготовлен переход в Cloud Storage: `storage.rules` разрешают только проверенному администратору создавать ограниченные WebP в публичном префиксе; имена по SHA-256 предотвращают повторную загрузку того же изображения. Пока bucket и правила не проверены в рабочем проекте, `BALI_IMAGE_STORAGE_ENABLED=false` сохраняет существующий совместимый режим компактных WebP в Firestore. Инструкция включения и ограничения — [OPERATIONS.md](OPERATIONS.md).

Старый `Code.gs` не является рабочим backend. `track.html` ведёт к личным заказам, `delivery.html` — к защищённой админке. Онлайн-оплата и синхронизация с Google Таблицей в текущем проекте не реализованы.
