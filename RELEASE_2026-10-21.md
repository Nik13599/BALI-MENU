# Интерфейс и подготовка гостевого сайта к релизу

## Интерфейс

- На всех экранах соседние афиши приближены к центральной и находятся позади неё.
- Сегодня — отдельный белый контур; предстоящие/идущие события — зелёный контур; выбранная афиша — зелёная заливка соответствующей даты. Архивные даты остаются прозрачными с красным контуром даже при выборе или старом RSVP.
- Точки показывают количество опубликованных мероприятий. Убраны градиентные сектора, ореолы точек и старые взаимоисключающие правила заливки.
- Календарь реагирует при смене центральной афиши во время жеста, до отпускания пальца. Убраны блокировки на 900/1100 мс.
- BALI ID открывается через общий маршрутизатор. Остальные страницы скрыты и недоступны для фокуса; прежние окна закрываются. Шрифт полей карты совпадает с номером, четыре пиктограммы привилегий перерисованы локальными SVG.
- «О клубе» и «Информация» используют общую шкалу элементов управления главной. Встроенная страница получает рассчитанные размеры кнопок из родительского окна; заголовок «Информация» больше не скрывается под шапкой.
- Убраны указания посетителю на настройку Firebase, неопубликованные правила, тестовый режим и подготовку политики разработчиком. Реальные ограничения предзаказов и оплаты сохранены.

Две отдельные неотмеченные галочки: обработка для аккаунта и передача зарубежным сервисам. Нет включения рекламных рассылок. Отказ оставляет доступ к публичному сайту. При восстановлении аккаунта с актуальной записью повторное окно не показывается. До успешного сохранения согласия регистрация и профиль не становятся доступны.

Фиксация: `users/{uid}/privacyConsents/2026-10-21`, только проверенный владелец, серверное время, неизменяемые версия и флаги согласия. Отзыв: `users/{uid}/privacyWithdrawals/2026-10-21`, серверное время и немедленное прекращение доступа к аккаунту в клиенте. Запрос нельзя переписать или отозвать через клиентский API. Администратор/директор имеют чтение. Другие посетители — нет. Совпавшее по времени подтверждение в другой вкладке повторно проверяется, не считается ошибкой регистрации.

**Эксплуатация:** оператор обязан рассматривать обращения на указанной почте и записи `privacyWithdrawals`, исполнять прекращение обработки/удаление в установленные сроки и документировать другое законное основание, если оно есть. Кнопка отзыва сохраняет обращение, а не автоматически удаляет бухгалтерские данные и записи заказов. Автоматическая отправка писем от имени оператора не подключена.

Политика раскрывает используемую инфраструктуру Google/Firebase, GitHub Pages, трансграничную передачу и риски. Оператору необходимо проверить фактические договоры с поставщиками, места обработки, сроки обязательного хранения, порядок рассмотрения обращений и утвердить текст. Наличие окна само по себе не является заключением о полном юридическом соответствии бизнеса.

## Публикация

Новые правила Firestore должны быть опубликованы **до** включения клиентской регистрации с обязательной фиксацией согласия. Используется существующий workflow `firestore-promo-rules.yml`: эмуляторы → GitHub OIDC → только Firestore Rules. Документы реальных пользователей в ходе проверки не создаются.

Регрессии проверяются в Playwright на 320×640, 390×844, 820×1180, 1440×900; тесты Firebase работают только в изолированном проекте `demo-bali-menu`. Публичный первый экран по-прежнему не ждёт SDK авторизации; новые стили включены в единственный гостевой CSS bundle.
