# Быстрый первый экран

Интерфейс гостя запускается после разбора своей разметки, независимо от загрузки внешних модулей Firebase. Локальные скрипты навигации, календаря и оформления также больше не стоят в очереди за авторизацией.

Общий `bali-public-reader.js` начинает публичные запросы предложений и афиш заранее. Гостевые представления получают данные через REST, пока SDK загружается; затем SDK продолжает обычные подписки в реальном времени. Новый серверный снимок имеет приоритет над запоздавшим REST-ответом. Пользовательские данные, авторизация и все записи по-прежнему используют исходный SDK.

Только четыре публичных меню сохраняются на пять минут в ограниченном локальном кеше. Сохранённые позиции показываются сразу, обновляются из сети и проходят прежнюю серверную проверку цен при оформлении. Ограничение/ошибка хранилища не мешает загрузке. Предложения, профили, бонусы и заказы в этот кеш не попадают. Запросы акций и мобильных фонов по-прежнему выбирают только опубликованные документы.

Убраны начальные надписи о загрузке предложений, получении актуальной информации, афиш, меню, контактов, карты и истории. Начальный спиннер меню удалён. Пустое состояние после подтверждённого ответа сервера и сообщения об ошибках важных операций сохранены.

Новые браузерные проверки намеренно удерживают загрузку Firebase SDK: первый экран, навигация, свежие предложения и меню должны работать до его завершения. Проверяются также показ сохранённого меню при двух незавершённых сетевых запросах, обновление его цены, преобразование дат событий и защита свежей публикации от запоздавшего ответа.

```sh
npm test
npm run check:styles
npx playwright test tests/instant-startup.spec.cjs
npm run test:browser
```

Свежие данные при первом посещении требуют сетевого ответа сервера; интерфейс и переходы между страницами этого ответа не ждут.
