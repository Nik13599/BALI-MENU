# BALI MENU: бесплатная приватная база на Google Таблицах

Схема: GitHub Pages (гостевой веб-интерфейс) → **Cloudflare Worker** (домен `baliminsk.by/api/bali-v3`) → **Google Apps Script** (Web App) → **закрытая Google Таблица**. Firebase Authentication Spark остаётся **только для Google-входа и проверки личности**. Платные Firebase Cloud Functions не требуются.

**Важно:** исходный сайт переключается на новую базу **только после успешной проверки**. До этого `bali-sheets-config.js` содержит `false`. Это защита от потери личных кабинетов при незавершённом подключении. Не публикуйте секреты, личные данные, токены или ссылку на редактирование базы в открытом репозитории.

## 1. Таблица уже создана

Основная база (приватная, совместно не используется):
https://docs.google.com/spreadsheets/d/1QxY-WgMwTT_5F3tdHxZICVbdUo4XOvgqI_7endBhOe0/edit

Исходник старого `BALI PREORDER` сохранён отдельно. В новой базе есть листы:
- Заказы, Позиции заказов, Меню, Мероприятия, Баннеры, Администраторы, История изменений, Настройки;

- BALI ID, Привилегии, Бонусы, История бонусов, BALI COIN, История BALI COIN.

Личные WebP-фотографии хранятся в **отдельной закрытой папке** Google Диска `BALI ID — личные фотографии (закрыто)`, а не в ячейках таблицы.

## 2. Установить скрипт, привязанный к этой таблице

1. Открыть указанную выше Google Таблицу через Google-аккаунт владельца.
2. В меню Google Таблицы выбрать **Расширения → Apps Script**.
3. Назвать проект `BALI MENU v3 Private API`.
4. Открыть `Code.gs`, удалить стартовый пример и полностью вставить содержимое файла
   `google-apps-script/BaliBackend.gs` из этого репозитория:
   https://github.com/Nik13599/BALI-MENU/blob/main/google-apps-script/BaliBackend.gs
5. Нажать **Сохранить**.
6. **Сначала** откройте закрытый лист **Настройки**, ячейку **B2**, и перенесите ключ в Cloudflare Worker как Secret `BALI_BRIDGE_KEY` (см. шаг 4). Нельзя запускать `baliCheckSetup` **до** переноса ключа в Cloudflare: скрипт удаляет ключ из таблицы.
7. Затем выберите в Apps Script функцию `baliCheckSetup` и нажмите **Run / Выполнить**. Разрешите доступ к этой таблице, папке фотографий и URL Fetch.
8. Этот запуск **переносит ключ из ячейки B2 в закрытые Script Properties** и стирает его из таблицы. В разделе **Executions** убедитесь, что проверка завершилась без ошибок. В таблице появится отметка `BALI_BRIDGE_KEY_MIGRATED`; значение B2 должно быть пустым.
9. Только после этого публикуйте Web App (шаг 3).

**Безопасность:** рабочий секрет не остаётся в пользовательской таблице. В продакшене Apps Script принимает ключ **только из Script Properties**, даже если в таблице появится ячейка с похожим названием.\n\n## 3. Опубликовать Apps Script

1. Нажать **Deploy → New deployment**.
2. Выбрать тип **Web app**.
3. `Execute as / Выполнять от имени`: **Me** (владелец).
4. `Who has access / Кто имеет доступ`: **Anyone**.
5. Нажать **Deploy** и пройти запросы авторизации.
6. Скопировать URL веб-приложения, заканчивающийся **/exec**. Сохранить его вне публичного исходного кода.

**Почему Anyone безопасен только с нашим посредником:** сам скрипт требует секрет `BALI_BRIDGE_KEY` **и** проверяет реальный Firebase ID token по Google Identity Toolkit на каждой защищённой операции. Без этих проверок режим Anyone делать нельзя. Прямая ссылка скрипта не является отдельной аутентификацией. При публикации обновлённого кода нужно изменить активную версию deployment.

## 4. Cloudflare Worker: отдельный бесплатный шлюз для домена BALI

Проект уже содержит готовый код:
https://github.com/Nik13599/BALI-MENU/blob/main/cloudflare-worker/BaliSheetsGateway.js

**Автоматически сделано:** Worker `bali-sheets-private-api` уже развёрнут на бесплатном тарифе. Маршрут `baliminsk.by/api/bali-v3*` подключён к нему; DNS сайта находится под Cloudflare Proxy. **Не создавайте второй Worker.**

**Остались два защищённых значения в Cloudflare:**

1. Откройте [Cloudflare Workers](https://dash.cloudflare.com/399972c0a0358037b0cb4d0d46ce69a3/workers-and-pages) и выберите `bali-sheets-private-api`.
2. В **Settings → Variables and Secrets** добавьте:
   - `SHEETS_SCRIPT_URL` как **Secret** со значением URL развёрнутого Apps Script `https://script.google.com/macros/s/.../exec`.
   - `BALI_BRIDGE_KEY` как **Secret** со значением **ячейки B2** закрытой таблицы BALI, вкладка `Настройки`, **до** запуска `baliCheckSetup`. После запуска скрипт очистит ячейку.
3. Нажмите **Deploy / Сохранить и развернуть**, если Cloudflare попросит подтвердить изменения.
4. Никогда не размещайте эти значения в GitHub, HTML, логах или общедоступном документе.

Подключённый инструмент Cloudflare не разрешил автоматическое сохранение защищённого секрета, поэтому значения ещё нужно ввести в интерфейсе владельца. Не путайте этот шаг с публикацией самого Worker, которая уже выполнена.

Альтернатива (если проект полностью переведён на Cloudflare Pages): использовать
`cloudflare-pages/functions/api/bali-v3.js` и те же два секрета. **Обычная публикация GitHub Pages сама по себе Cloudflare Pages Functions не запускает.**

## 5. Назначить первого администратора в таблице

Откройте вкладку **Администраторы**. Во **второй строке**:
- A = Firebase UID проверенного аккаунта владельца, если он известен; иначе оставить пустым;
- B = **точный email** Google-аккаунта владельца (не выдумывать адрес);
- C = `admin`;
- D = `TRUE`;
- E = имя (необязательно).

**Строка владельца уже создана и проверена:** `kolyaselekh@gmail.com` / `admin` / `TRUE`. Не нужно добавлять её повторно. Не вставляйте пароли и сервисные секреты. Сервер позволяет назначать роль только вручную владельцем или через защищённую административную операцию и **не** выдаёт права администратора из параметров браузера.

Для доступа сотрудников только к предзаказам можно добавлять строки с ролью `staff` и нужным подтверждённым Google email. В новом варианте сотрудники должны входить через **Google**, а не через неработающую платную Firebase-функцию создания паролей.

## 6. Проверить сервер, затем переключить сайт

1. После публикации Worker отправьте с сайта `POST /api/bali-v3` с JSON `{"action":"health"}`.
2. Ожидается `{"ok":true,"data":{"status":"ready","version":3}}`. **Если 404/403/503/502, переключать сайт нельзя**.
3. Проверить тестовый вход владельца и `me` с валидным Firebase ID token.
4. Проверить `consentAccept`, `profileSave`, `activateCard`, `card`, `coinHistory` и выдачу прав неавторизованному пользователю (ожидается 401/403).
5. Только после этого изменить `bali-sheets-config.js` на `true` и опубликовать страницу.
6. Повторить тест на двух гостевых Google-аккаунтах. Гость №1 **не должен** видеть или менять профиль/баланс гостя №2.

## 7. BALI COIN

**BALI COIN** — целочисленные внутренние баллы лояльности, **не реальные денежные средства** и не платёжный инструмент. На лицевой стороне карты показывается подтверждённый сервером баланс, либо «—», если он недоступен. На странице BALI ID в истории операций показываются начисления/списания. Административная панель **Гости → BALI COIN** поддерживает начисление и списание с обязательным комментарием, с записью в отдельный журнал. Не выдавайте гостю права редактирования этих листов.

Правила уровней Privilege и бонусов хранятся **отдельно** от BALI COIN. Шесть основных уровней: Member, Silver, Gold, Platinum, Black, Private; дополнительно Resident DJ. Бонусы (входы, шоты, коктейли, кальяны) учитываются поштучно.

## 8. Что НЕ следует считать готовым до тестового запуска

- Невозможно подтвердить работу реального Google Apps Script до его публикации через редактор Apps Script и получения URL.
- Старый Firebase-регистратор сотрудников по логину/паролю **не запустится** без Cloud Functions. Бесплатный вариант — сотрудники со своим Google-входом и назначенным `staff`; для них нужно переключить BALI STAFF на новый backend.
- Генератор, сканирование и списание многоразовых/разовых QR-бонусов, функции директора и некоторые редакторы админки всё ещё используют Firebase и требуют отдельной адаптации. В режиме Sheets неподключённая QR-функция должна быть отключена, а не показывать фиктивный успех.
- Это схема **без обязательной подписки/Blaze**, но лимиты бесплатных Google Apps Script и Cloudflare Worker сохраняются.
- Приватность новой таблицы уже подтверждена: общий доступ отключён, только владелец.
